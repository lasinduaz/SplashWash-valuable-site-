Web security basics

This page explains the risks around SQL injection and cross-site scripting in a safe, defensive way. It intentionally does not include exploit payloads.

SQL Injection

Happens when untrusted input is concatenated into SQL statements.

Defenses: prepared statements, parameter binding, least-privilege database users, and server-side validation.

Cross-site scripting

Happens when untrusted data is rendered into HTML or JavaScript without escaping.

Defenses: output encoding, safe DOM APIs like textContent, input sanitization, and a strict Content Security Policy.

Good testing habits

Use local labs, test accounts, and tools like OWASP ZAP only in isolated environments you control.

Safe examples

Instead of attack strings, focus on secure patterns like:

  • PDO::prepare() with bound parameters
  • textContent instead of innerHTML
  • Escaping output before rendering user data
